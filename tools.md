# 1.GDB



## 快速入门

使用条件：编译时开启：

```shell
gcc test.c -o test -O0 -g
```

用GDB运行程序：

```shell
gdb test
```



## GDB的命令

| 命令名称               | 命令功能           | 使用语法                   |
| ---------------------- | ------------------ | -------------------------- |
| `list/l`               | 看文件内容         | `[文件名:][行号]|[函数名]` |
| `run/r`                | 运行程序           |                            |
| `break/b`              | 打断点             | `[文件名:][行号]|[函数名]` |
| `continue/c`           | 继续运行           |                            |
| `step/s`               | 单步进入           |                            |
| `next/n`               | 单步跳过           |                            |
| `finish`               | 跳出本次函数调用   |                            |
| `info break/ib`        | 查看断点信息       |                            |
| `delete [num]`         | 删除断点           |                            |
| `ignore [num] [count]` | 忽略num断点count次 |                            |



## GDB查看监视

| 命令名称         | 命令功能     | 使用语法 |
| ---------------- | ------------ | -------- |
| `print/p 表达式` | 打印         |          |
| `display 表达式` | 持续监视     |          |
| `info display`   | 展示监视信息 |          |
| `undisplay 编号` | 删除监视     |          |

## 检查崩溃的程序

类似于航空领域的**黑匣子**，core文件，存储着程序崩溃时刻内存的堆栈。



**试验：写一个一定会报错的程序**

```c
int main(){
	int *p = 0;
	*p = 1;
}
```



编译并运行程序：

```shell
$ gcc error1.c -o error1 -g -O0
$ ./error1
Segmentation fault (core dumped)
```

这时候如果ls一下当前目录，其实可能看不到core文件；

所以，需要取消对 Core Dump（核心转储文件）大小的限制：

```shell
ulimit -c unlimited
```

再次运行程序，等待崩溃后ls如果**还是看不到**core文件：

```shell
su root
echo core > /proc/sys/kernel/core_pattern
ulimit -c unlimited
./error1
```

这时候就有core文件了，查看一下core：

```shell
gdb error1 core

...
Core was generated by `./error1'.
Program terminated with signal SIGSEGV, Segmentation fault.
#0  0x00005bbc579cf13d in main () at error1.c:3
3               *p = 1;
```
